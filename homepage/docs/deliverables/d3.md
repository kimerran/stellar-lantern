# D3 — Scanner in the wallet

**Statement of Work:** Deliverable 3 · **Target:** Week 3 (21–27 Sep) · **Status:** Shipped in the wallet (0.3.0, 25 Sep). Screen recording and QA sign-off pending

The D2 scanner now runs inside the Lantern wallet, on the Chrome extension and Android, in the review before every signature. A transaction's effects, its risk verdict, a plain-language sentence and a live registry check of every counterparty are shown before the Sign button, and a flagged recipient can be reported to the on-chain registry from the same screen. This is where the §6.3 metrics (transactions scanned, wallets that ran a scan) started to accrue.

## What a user can do when this is done

In the Lantern wallet on Chrome or Android, on testnet:

- **Every transaction is reviewed before it's signed**: a payment, a swap, a lending action, a guardian change, a request from a mini-app. The review shows what leaves and arrives, and for whom, a risk verdict, and one plain-language sentence written by the hosted model (or the rules-based one, labelled, if the model can't be reached).
- **Every counterparty is checked against the on-chain registry, live.** A reported recipient raises a high-risk warning that holds the Sign button until the user deliberately confirms. A recipient the registry couldn't be read for never reads as clean: it needs a second, deliberate confirm.
- **Report an address in one tap** from the review, with a reason the user must choose and the fee shown before signing.
- **Just before submitting, the transaction is simulated and screened again.** If anything changed since the review (the recipient was reported, the effects drifted), the user sees it before it's sent.

## Scope notes

- **Testnet only for screening.** Mainnet has no registry deployed, so a Mainnet review says the registry is unavailable instead of claiming a check it didn't make.
- **Advise and gate, never block.** A high-risk verdict holds the Sign button until the user deliberately confirms; the user can always proceed. The AI sentence is never allowed to say otherwise.
- **The verdict never comes from the AI.** It comes from deterministic code; the hosted model only writes the sentence, and any failure falls back to the rules-based one with the same verdict.
- **The wallet's report is confirmed on its own sheet**, which shows the address, the chosen reason, the fee and that the report is public, rather than going through the transaction scanner. The public playground's report (Deliverable 4) does go through the scanner first.

## Implementation choices

- **One adapter, no rewritten screens.** The pipeline's result is mapped onto the shape the review screens already rendered, so every screen gained screening and the AI sentence without being rewritten.
- **The key stays on the server.** The wallet asks the Lantern API for the sentence; no model key ships in the extension or the APK.
- **A tighter budget at Confirm.** The re-check runs on the path to every signature, so it has its own short deadline and never answers from the review's cache: the point is to see a report that landed after the review.
