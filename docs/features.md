- 2026-07-03 — Recovery: **guardian co-signature tally** (`collectedSignatureWeight` / `hasThresholdSignatures` in `core/recovery/guardians.ts`). The last non-UI piece of the recovery coordination flow (#23 M1, item 4): as guardians co-sign a recovery tx out-of-band via `SIGN_ONLY` (#33), these compute how much signature weight has been collected (via the SDK's `WebAuth.gatherTxSigners`, summing only the account's known signers) and whether it has reached the account's high threshold K — i.e. when it's safe to submit. - 2026-07-03 — Recovery: **`buildRecoveryXdr` — install-new-key recovery transaction** (`core/recovery/guardians.ts`). Completes the transaction-building side of guardian recovery (#23 M1, item 4): when the owner key is lost, the fresh device drafts one `setOptions` that installs its new key at owner-level weight (`N+1`, mirroring the setup so it operates normally) and disables the lost master (`masterWeight 0`). It's a HIGH-threshold change, so under the `highThreshold = K` the setup installed it's authorized by exactly K guardian co-signatures (each collected out-of-band via `SIGN_ONLY` #33). Thresholds + existing guardian signers are left untouched, so the account stays guardian-protected. Validates the new key, rejects self. Also tightens `buildGuardianSetupXdr`'s guardian cap from 20 → **19** (`MAX_SIGNERS − 1`) so a recovery signer slot is always reserved — otherwise an `N=20` setup would produce a permanently unrecoverable account within Stellar's 20-signer limit. Unit-tested via the scan decoder (#31) + confirmed scanned high-risk and explained as *"adds signer … removes your own key's signing power"* (#31/#37), plus the 19-guardian headroom boundary. The Guardians & Recovery UI + QR/paste co-sign hand-off remain the rest of #23. (#42, part of #23)
- 2026-07-03 — Recovery: **`buildGuardianSetupXdr` guardian multi-sig setup** (`core/recovery/guardians.ts`). Composes the setOptions primitive (#35) into the actual weighted-multisig setup transaction for guardian social recovery (#23 M1, items 3–4): adds each guardian as a weight-1 signer (one op each), then sets the account's weighting. Security-critical policy (decouples owner power from the guardian quorum, since Stellar puts **Payment on the *medium* threshold but signer `setOptions` on the *high* threshold**): owner `masterWeight` + `low`/`medThreshold` = `N+1` (strictly above all guardians combined → guardians can **never** authorize a payment/offer/trustline change), and **only** `highThreshold` = `K` so any K guardians can co-sign the recovery `setOptions` and nothing lower. Owner keeps full solo control, never locked out. Validates distinct valid keys, `1 ≤ K ≤ N ≤ 20`, rejects self-as-guardian. Pure/offline; unit-tested by round-tripping through the scan decoder (#31), asserting the on-chain invariant (K guardians clear high but not medium), and confirming the scanner flags it high-risk `block_confirm` (#31/#37). The Guardians & Recovery UI + QR/paste co-sign hand-off remain the rest of #23. (#41, part of #23)
